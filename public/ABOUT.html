What is this?

Estudely Packet Explorer opens packet capture files (pcap and pcapng) in your browser and shows what is in them. Wireshark, compiled to WebAssembly by Wiregasm, decodes the packets in a Web Worker on your device. The app turns the decoded packets into views: Overview, Hosts, Connections, Network, Packets, DNS, HTTP, Files, TLS, QUIC, SSH, DHCP, ARP and ICMP, plus a comparison of two captures.

How it works

You choose or drop a capture file. The browser reads it from your disk and passes it to the decoding engine running in a Web Worker. A script inside the engine records the fields the views need; the page builds its tables and charts from those records. You can add a TLS key log file to decrypt sessions it matches. Nothing here needs an account or a server of ours.

What leaves your device

Captures and key log files are never uploaded. The app contains no code that sends them anywhere, and the page's security policy only allows it to request files from its own address.

The page requests only its own static files: the app, fonts, and the decoding engine (about 20 MB, compressed). Cloudflare hosts the site and, like any web host, sees ordinary request metadata for those files, such as your IP address, browser type and the file requested. The site runs no server code of ours and has Workers request logging turned off.

The app has no analytics. Links to other sites (for example the DB-IP download pages in the Hosts view) only load when you open them.

What stays on your device

  • Offline copy. A service worker saves the app's own files and the engine in your browser's Cache Storage (caches named epx-shell-… and epx-engine-…) so the app works offline. It caches only files the build lists; captures are never stored. The start screen shows how much space it uses.
  • Colour theme. Your choice (system, light or dark) is kept in localStorage under epx-theme.
  • Country and ASN data. Only if you import DB-IP Lite files in the Hosts view, the parsed address ranges are kept in IndexedDB (database estudely-local-ip-data) until you remove them. The imported file is read from your disk and matched locally.

To clear them: use Remove next to each imported database in the Hosts view, and clear this site's data in your browser settings (this also removes the offline copy and the theme choice). Open captures and key logs exist only in the tab's memory and are gone when you close the capture or the tab.

Limits

The first 1 GiB of capture data is analyzed; if there is more, results are marked partial. A warning appears above 250 MiB. See Known limitations below for what the decoding does and does not show.

Known limitations

  • HTTP/2 requests are shown when Wireshark reconstructs the header block, including after a matching key log. HTTP/3 is not turned into request rows.
  • TLS and QUIC decrypt only when a matching key log is supplied, and only for what Wireshark then exposes. TLS 1.3 certificates stay encrypted unless the decrypted handshake exposes them. DoH and DoT are not shown as DNS queries or request rows.
  • TLS certificates are shown only when sent in cleartext (TLS 1.2 and earlier). Trust is not checked.
  • Names come only from the capture itself (DNS, mDNS, NBNS, DHCP, TLS SNI, HTTP Host). Ports are traffic observations, not open-port checks. No device or OS identification.
  • The first 1.00 GiB of capture data is analyzed; if there is more, results are marked partial. Inputs larger than 1 GiB are not refused. Large captures take about a minute per 400,000 packets.
